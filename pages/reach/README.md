# Reach (proposed rework)

> English | [日本語](./README-ja.md)

Whether sockat reaches a long path, by which route, and if not, why, for each combination of conditions. Built for [the proposal to rebuild the routes around resolve and base B](../../docs/issue/2026-11-20-resolve-and-persistent-base.md) (Japanese; no fork, no last resort). The design is not implemented yet, so the numbers are estimates from the lengths of the spellings.

- Page that filters by the conditions you choose: [index.html](index.html?lang=en) (without JS, read this README)
- Source of truth: [model.json](model.json). This README (English and Japanese) and `data/` are generated by [gen.py](gen.py) (`just reach`); do not edit them by hand. `just reach-check` catches drift
- The fork-cwd technique and where it reaches: [fork-cwd](../fork-cwd.md)

## How rows are folded

- One table per operation and OS. A row is a combination of conditions; the columns are the conditions and the result
- Every combination is computed. Rows with the same result (reached, route, spelling, reason, basis) that differ in the value of one condition only are merged into one row, repeatedly until nothing merges
- The file name, and the shorter of the original and the relative path, are split into bands at the lengths where some route's spelling starts or stops fitting. Within a band the result does not change (gen.py checks both ends of each band)
- A condition that is "any" in every row of a table gets no column; it is listed above the table under "Conditions with no effect"
- Base lengths are typical values (the bases table under "Conditions"). The directory is assumed deep enough that the path is over the standard length; the whole path's length has no effect up to PATH_MAX
- Languages are split only where a route they cannot build (lacks) changes the result

## Estimates and measurements

- A cell whose basis is "estimate" is only computed from the spelling formulas and typical values in model.json
- A "measured" cell names the conformance scenes ([conformance/cases.json](../../conformance/cases.json)) where the current implementations took the same route with the same result as computed. Applied only to routes the rework does not change (at, at-direct, proc, proc-direct, relative, symlink-file, thread-cwd, widened) and to the unreached rows of the default bind for languages without fork (py, go), and only for scenes whose conditions are all known
- Inputs that were measured: which OSes' bind follows a symlink ([findings](../../docs/findings/2026-11-19-bind-through-file-symlink.md), Japanese), that another uid cannot traverse a 0711 directory under a 0700 parent (the measurements in the issue), and that docker's seccomp refuses `unshare` ([conformance.md](../../docs/design/conformance.md), Japanese)

Assumptions of the estimates:

| Value | Bytes | Meaning |
|---|---|---|
| `rand` | 10 | the random names of D and R (10 alphanumerics) |
| `B` | 17 | the length of B's name. The name is still open (the issue); estimated at 17 bytes, the same as the current name sockat.XXXXXXXXXX |
| `pid` | 7 | the digits of <pid> in procB. 7 for Linux's pid_max 4194304 (a smaller pid reaches a longer file name by as much) |
| `fd` | 2 | the digits of the fd number. 2, as in the SPEC's "about 79" for proc |
| `name_max` | 255 | the file name limit (NAME_MAX). The file name bands in the tables go up to it |
| `widened` | 253 | the path length that fits a widened sockaddr on Apple OSes (widened in the SPEC) |
