# DR-0006: 先頭以外に NUL を含むパスは長さによらず引数の誤りにする

- Status: Active
- Date: 2026-11-18

## Context

- 短いパスは標準にそのまま渡す
- Go の標準は NUL で黙って切り詰め、別の場所にソケットを作る
- NUL を含む短いパスも標準に渡すか決める必要がある

## Decision

- 先頭以外に NUL を含むパスは、長さによらず標準に渡さず引数の誤りにする
- Linux / Android で先頭が NUL のパス (abstract namespace) はファイルではないので対象外。長さによらず標準にそのまま渡す (Python の標準ではこれが abstract の普通の書き方。統括の裁定、kawaz 承認 2026-11-18)
- 標準が NUL で黙って切り詰める言語は、README の「標準と違う点」に書く

理由:

- 利用者の指定と別の場所にソケットができるのを防ぐ
- 標準が元から NUL をエラーにする言語は振る舞いが変わらない

## Alternatives Considered

- 案 A: 短いパスは標準のまま渡す
  - 不採用理由: 標準が切り詰める言語で、別の場所にソケットができる

## Consequences

- 「短いパスは標準と同じ」に NUL の例外が 1 つ入る
