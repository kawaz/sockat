# DR-0004: 標準ライブラリに渡す長さはその言語の標準ライブラリが受け付ける長さ

- Status: Active
- Date: 2026-11-18

## Context

- sockat は短いパスを標準ライブラリにそのまま渡し、それを超えたパスだけを経路に回す
- 標準ライブラリが受け付ける長さは言語で違う。多くは `sun_path` − 1、Java は `sun_path` − 2
- 境界を `sun_path` − 1 に固定するか、言語ごとに決めるか決める必要がある

## Decision

| 用語 | 長さ |
|---|---|
| 標準ライブラリに渡す長さ | その言語の標準ライブラリが、パスを変えずに広げない sockaddr に入れて受け付ける最長。これ以下は標準ライブラリにそのまま渡す |
| sockaddr に入る長さ | `sun_path` − 1。経路が作る綴りの条件 |

- 経路の綴りを標準ライブラリが受け付けない時は、標準ライブラリと同じ設定の自前のソケットで同じアドレスを渡す
- 標準ライブラリがそれより長いパスを通す仕組み (黙って切り詰める Node 22 の Linux、広げた sockaddr で bind する libuv の macOS、`/proc/self/fd` やスレッドの cwd で自前に迂回する Bun) は使わない。どれも綴りが元のパスと違い、bind では読む側を壊すか、後で無関係なファイルに当たる (統括 2026-11-21、sockat-ts の調査)

理由:

- 標準ライブラリが通すパスは標準ライブラリと完全に同じ振る舞い、をどの言語でも保つ

## Alternatives Considered

- 案 A: `sun_path` − 1 のまま、標準ライブラリが受け付ける長さが短い言語を例外として書く
  - 不採用理由: 標準ライブラリが通すパスの一部を sockat の経路が扱うことになり、標準ライブラリと同じ振る舞いが崩れる

## Consequences

- 標準ライブラリに渡す長さは言語ごとに変わり得る。標準ライブラリの版が長いパスを広げた sockaddr や迂回で通すようになっても変わらない
- 各実装は標準ライブラリの境界を標準ライブラリ自身で試験する
