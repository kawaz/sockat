# DR-0011: bind に渡す綴りにはランダムな部品を挟む

- Status: Active
- Date: 2026-11-19

## Context

- カーネルは bind に渡された綴りをそのまま覚え、`getsockname` / `getpeername` はそれを返す
- 上のライブラリや利用者はその綴りでファイルを消す (Python の asyncio の後始末、Go の `UnixListener.Close` の unlink、利用者の `remove_file(local_addr)` 等)
- 長いパスの経路の綴りは、後で別の文脈で解決され直す

| 経路 | bind の綴り | 後で解決すると |
|---|---|---|
| /proc | `/proc/self/fd/<n>/<ファイル名>` | 閉じた fd の番号が使い回され、別のディレクトリの同名ファイルに当たる (sockat-rs が docker で実測、無関係な `other/s.sock` を消した) |
| スレッド cwd / fork | `<ファイル名>` | プロセスの cwd の同名ファイルに当たる (sockat-py が macOS で実測) |
| 相対パス | cwd からの相対パス | cwd が変わらなければ元のソケット、変わると別の場所 |
| symlink | `<置き場>/sockat.XXXXXXXXXX/<ファイル名>` | symlink を消した後なので何にも当たらない |

## Decision

bind に渡す綴りには必ずランダムな部品を挟み、後で別の文脈で解決されても何にも当たらないようにする。bind は安全な綴りの経路だけを、綴りの短くなる順に試す。

| 経路 | bind の綴り | 作り |
|---|---|---|
| /proc | `/proc/self/fd/<fd>/<乱数>/<ファイル名>` | 置き場に自分専用のディレクトリ (DR-0008 と同じ作り・確認・片付け) を作り、その中にソケットのディレクトリを指す symlink `<乱数>` を作る |
| symlink | `<置き場>/sockat.XXXXXXXXXX/<ファイル名>` | 変えない |
| スレッド cwd / fork | `<乱数>/<ファイル名>` | 自分専用のディレクトリに `fchdir` し、その中の symlink `<乱数>` を通す |

- `<乱数>` は `sockat.` の symlink と同じ 62 種 10 文字
- 順番: /proc → symlink (/proc より 5 バイト前後短い) → スレッド cwd / fork (いちばん短い)。相対パスは bind では試さない (扱いは未確定)
- 片付けで symlink とディレクトリを消すので、後で fd が使い回されても cwd が何でも `<乱数>` のエントリは無い
- connect 系は変えない (connect した側のソケットは bind されず、綴りが相手に残らない)

理由:

- 目的は無関係なファイルを消さないこと。綴りの中に自分しか知らず既に消した名前があれば、どこで解決しても当たらない

悪い面:

- ファイル名の上限が `<乱数>/` の 11 バイト分短くなる (/proc の経路の bind はおよそ 79 バイト、fd の桁で変わる。スレッド cwd / fork は Linux 96、Apple の OS 等 92)
- 長いパスの bind のたびにディレクトリと symlink を作って消す
- 上のライブラリが元のパスのソケットのファイルを自動で消すことは、どの綴りでも効かない (kawaz が許容)

## Alternatives Considered

- 案 A: 今のまま
  - 不採用理由: 無関係なファイルを消しうる
- 案 B: 文書で注意するだけ
  - 不採用理由: 消すのは利用者のコードでなく上のライブラリで、利用者が避けられない

## Consequences

- 試験: bind した後に返る綴り (`getsockname`) をそのまま unlink / stat しても、無関係なファイル (fd の番号を使い回させた別のディレクトリの同名ファイル、cwd の同名ファイル) に当たらない
- 「どこから届かなくなるか」の bind の上限が下がる

## 未確定

- 安全な綴りを作れない時 (どの置き場にも自分専用のディレクトリを作れない等) に、安全でない綴りの経路 (今の /proc、ファイル名だけ) に進むか、`ENAMETOOLONG` にするか
- bind で相対パスの経路をどう扱うか

| 案 | 内容 | 悪い面 |
|---|---|---|
| 使わない (今の SPEC) | bind の順番から外す | cwd に近いパスで短い綴りを使えない |
| 今の綴りで使う | cwd からの相対パス | cwd が変わると別の場所に当たる |
| 自分専用のディレクトリへの相対パスに `<乱数>` を挟む | cwd から置き場の自分専用のディレクトリへの相対パス + `<乱数>/<ファイル名>` | symlink の経路より短くなることがほぼ無い |

- FreeBSD の bindat の bind の綴り (ファイル名だけ) も cwd の同名ファイルに当たりうる (未確認)。同じ作り (自分専用のディレクトリの fd に `bindat`、`<乱数>/<ファイル名>`) にするか
