# DR-0019: bind と resolve は、相対パスを cwd で絶対パスにしてから扱う

- Status: Proposed (方針は kawaz 2026-11-22。細部は統括の案で、「裁定」の節の問いが残っている)
- Date: 2026-11-22

## Context

- 相対パスで bind すると、カーネルが覚える綴りは相対のままになる。後で cwd が変わると、その綴りは別の所を指す (`Spelling` の `CwdRelative`)
- 相対の綴りで起きる事故

| 場面 | 起きること |
|---|---|
| listener を閉じる時にアドレスの綴りで unlink する標準 (Go の `UnixListener.Close`) | bind の後で cwd を変えていると、ソケットのファイルが消えないか、別の場所の同じ名前のファイルを消す |
| 閉じた時点の cwd で、渡されたパスを unlink する標準 (Node・Bun) | 同じ |
| DGRAM の受け手が、送り手のアドレスへ返信する | 受け手の cwd が違うと届かない ([実測](../findings/2026-11-22-dgram-reply-to-relative-sender.md)) |
| 深い cwd で、絶対パスなら長すぎるので相対パスで bind する (よくある回避策) | 上の全部に当たる |

- [DR-0017](DR-0017-resolve-through-persistent-base.md) は、相対パスを入口で絶対パスにする案 (案 AC) を「短い相対パスが標準と違う経路に回り振る舞いが変わる」として採らなかった。その時の設計は bind のたびに乱数の名前を挟んですぐ片付ける形で、絶対にすると手数と片付けが増えた
- 今の設計は、綴りを残して使い回す (既定の bind の link-dir の E は、ディレクトリごとに 1 つ)。絶対にしても増える物が少なく、上の事故を未然に防ぐ意味が加わる (kawaz 2026-11-22)
- CLI の `resolve` は、相対パスを絶対にしてから長さで分けると決めてある ([DR-0018](DR-0018-cli-resolve-with-reused-hashed-link.md))

## Decision

### 絶対パスにする操作

| 操作 | 相対パスを受け取ったら |
|---|---|
| bind 系 (`bind`・`bind_ex`・`datagram::bind`・`datagram::bind_ex`) | 絶対パスにしてから扱う |
| resolve (`resolve_for_bind`・`resolve_for_connect`) | 絶対パスにしてから扱う (返した綴りは、後で cwd が変わった後にも使われうる) |
| connect 系 (`connect`・`connect_nonblocking`・`datagram::connect` と各 `_ex`) | 変えない (connect の綴りは相手に残らない。相対のまま渡すのが一番手数が少ない) |

### 絶対パスの作り方と、その後

1. 引数の形の検査 (空のパス、NUL、`Options.base` の形) は今のとおり先に行う。abstract の名前は対象外
2. 相対パスなら、プロセスの cwd (`getcwd`) を前に付けて絶対パスにする。`..` と途中の `.` は字句で畳まない (`a/sym/..` が別のディレクトリになる)。先頭の `./` だけは落とす (cwd 自身を指すので、落としても同じ所)
3. 絶対にした形が標準に渡す長さ以下なら、それを標準に渡す。綴りは絶対パスで、`Spelling` は `Original`
4. 超えるなら、長いパスの経路に進む (今の長い相対パスと同じ。`Linked` 等)
5. cwd を引けない時と、絶対にした形でどの経路も使えない時は、元の相対パスが標準に渡す長さ以下なら、相対のまま標準に渡す (`Spelling` は `CwdRelative`)。標準で届く所に届かなくならないようにする

- `CwdRelative` が返るのは 5 の場面だけになる
- 相対パスの `remove()` のための cwd の見張り (呼び出しの前後で cwd の `(st_dev, st_ino)` を比べる) と、標準がパスとして読まない綴りに `./` を付ける扱い (Node の数値に読める文字列、Go の illumos の `@`) が要るのも、5 の場面だけになる

理由:

- 既定の `bind` の利用者は `Spelling` を見ないので、`CwdRelative` で知らせても事故に気づけない。絶対にすれば、利用者が何もしなくても起きない
- 変わるのは「カーネルが覚える綴りが相対か絶対か」で、ソケットのファイルができる場所は変わらない
- 5 で相対のまま渡す道を残すので、標準より届かなくなる場面ができない

悪い面:

- 短い相対パスで、カーネルが返すアドレス (`getsockname`、相手の `getpeername`、`ss`・`lsof` 等) が相対でなく絶対になる (標準と違う)。アドレスの文字列を、渡した相対パスと比べるコードは合わなくなる
- 深い cwd で短い相対パスを bind すると、標準なら何も作らずに済んだ所で、置き場に B・D・E ができる。「短いパスは標準にそのまま渡す」が、相対パスには当たらなくなる
- 相対パスの bind のたびに `getcwd` が 1 回増える
- `getcwd` と bind の間に他のスレッドが cwd を変えると、呼んだ時点の cwd の場所に作る (標準の相対パスの bind は bind の時点の cwd)
- 4 言語の実装と適合試験を直し、0.x の minor を上げる (振る舞いが変わる)

## Alternatives Considered

- 案 A: 今のまま、`CwdRelative` で知らせるだけにする
  - 不採用理由: 知らせを見るのは `_ex` と resolve を使う人だけ。消すのは利用者のコードでなく上のライブラリのことが多く、利用者が避けにくい
- 案 B: connect 系も絶対にする
  - 不採用理由: connect の綴りは相手に残らないので意味が無く、手数だけ増える
- 案 C: 絶対にした形で届かない時はエラーにする
  - 不採用理由: 標準なら届く短い相対パスが、sockat に置き換えると届かなくなる
- 案 D: `..` も字句で畳んで正規化する
  - 不採用理由: `a/sym/..` はカーネルでは symlink の先の親を指す。字句で畳むと別のディレクトリになる
- 案 E: cwd を前に付ける代わりに realpath で絶対にする
  - 不採用理由: symlink を解いた別の綴りになり、利用者が渡したパスの見え方が変わる。短いパスでは要らない手数

## Consequences

- SPEC (短いパス、bind の順、`Spelling`、`remove`、長いパスで標準と違う点、使ってはいけない書き方、試験の観点) と DR-0017 の案 AC の記述、届く範囲の表を直す
- 各言語の実装と適合試験の場面を直す
- README と各言語の README の「短いパスは今までどおり標準にそのまま渡す」の言い方を見直す

## 裁定

- kawaz (2026-11-22): 相対パスを絶対にする方向に変える
- 統括の案 (裁定待ち): 5 の、届かない時は相対のまま標準に渡す形 ([QUESTIONS](../QUESTIONS.md) の RP-Q1)。bind 系と resolve だけにして connect 系は変えない (RP-Q2)。先頭の `./` だけ落とす
