# DR-0013: any 系は「何かを失ってでも届かせる」opt-in の API で、何を失ったかを返す

- Status: Superseded by DR-0015
- Date: 2026-11-19

## Context

- 既定の bind / connect は、標準と同じに振る舞い、安全でない綴りを残さない経路だけを使う ([DR-0012](../DR-0012-own-directory-and-thread-cwd.md))。そのため届かない環境が残る
  - fork の無い言語 (Python、Go) の bind: NetBSD / OpenBSD / illumos の長いパス全部、スレッド cwd も `/proc` も使えない Linux、`pthread_fchdir_np` が無い Apple の OS
  - connect: fork でしか届かない所
- 届かせる手はあるが、どれも何かを失う (fork の副作用、他の利用者が作り直せる綴り)。失ってでも届かせたい人と、失いたくない人がいる
- 既定の API に並ぶと、補完などで利用者がどちらを使うか迷う

## Decision

### any の意味

- any は「何かを失ってでも届かせる」(fork の意味ではない)。何を失うかは any 系の説明に並べる
- any 系は既定の API に出さず、使う人が選んで有効にする仕組みの後ろに置く

| 言語 | 置き場 |
|---|---|
| Rust | feature `any` (docs.rs では全 feature を有効にし、feature が要ることを表示する) |
| Python 等 | 既定で import されない別のモジュール等。各言語の DR で決める |

### any 系の操作

| 操作 | 既定の操作との違い |
|---|---|
| `bind_any` | 既定の bind の経路を全部試した後、最後に置き場の symlink を試す。fork のある言語 (Rust) にも置く (3 言語で API をそろえる) |
| `connect_any` 系 | 既定の connect の経路を全部試した後、最後に fork を試す。fork を作れない言語は、既定の connect と何も変わらないので出さない ([DR-0002](../DR-0002-no-connect-any-without-fork.md)) |

### bind_any の置き場の symlink

- 置き場に、ソケットのディレクトリを指す乱数の名前の symlink を作り、`<置き場>/sockat.XXXXXXXXXX/<ファイル名>` で bind して、すぐ消す
- 置き場は、持ち主だけが書ける置き場を先に、共有の置き場を最後に試す
  - 持ち主だけが書ける: 持ち主が実効 uid で group と other が書けない (`$XDG_RUNTIME_DIR`、macOS の `$TMPDIR` 等)。綴りを作り直せるのは自分だけなので、片付けた後の綴りは何にも当たらない
  - 共有: sticky が立ち、持ち主が root か実効 uid (`/tmp` 等)。他の利用者がその綴りを (Linux の `/proc/net/unix` 等で見て) 作り直せ、上のライブラリや利用者が綴りで unlink した時に、相手の選んだディレクトリの同じ名前のファイルを消させうる

### 何を失ったかを返す

any 系は、標準の型 (listener / stream) と一緒に、次の 3 つを返す。

| 項目 | 中身 |
|---|---|
| `losses` | 失ったものの名前の並び (下の表の名前。何も失っていなければ空)。分岐に使う |
| `route` | 通った経路の名前 |
| `skipped` | 試して使えなかった経路の並び (試した順)。各要素は `{ name: 経路の名前, reason: 使えなかった理由 }` |

| 失ったものの名前 | 失ったもの | 付く時 |
|---|---|---|
| `respelled` | カーネルが返すアドレスが元のパスでない。標準が listener を閉じる時に消す言語でも消えず、元のパスで消す必要がある (`_ex` の `discard()` 等) | bind が標準以外の経路を通った |
| `cwd-relative` | カーネルが覚えた綴りが cwd からの相対パス (渡したパスがそのまま標準に渡った)。cwd を変えた後にその綴りで unlink / stat すると別の場所に当たる。sockat が経路で失わせたものでなく標準が元から持つ危険だが、any 系を選んだ利用者は何を失ったかを知りたいので知らせる (kawaz 裁定 2026-11-19) | 相対パス (abstract の名前は除く) で bind が standard を通った |
| `forked` | fork の副作用 (子が fd の複製を持つ、`SIGCHLD`、`pthread_atfork` 等) | fork・fork-sockdir・fork-direct を通った |
| `recreatable-spelling` | カーネルが返す綴りが共有の置き場 (`/tmp` 等) を通る。名前は乱数なので事前には当てられないが、bind の後は他の利用者に見えうる (Linux の `/proc/net/unix`)。他の利用者がそれを作り直した後にその綴りで unlink すると、相手の選んだディレクトリの同じ名前のファイルを消しうる。元のパス (`discard()` 等) で消せば当たらない。名前の長さは防御でない (名前は bind の後に見える) | `bind_any` が共有の置き場の symlink を通った |

- 名前は約束で、変えずに足すだけ。知らない名前は「何かを失った」とだけ読むと説明に書く。各言語は enum 等で表してよいが、文字列にした時は SPEC の名前と同じにする
- connect の綴りは相手に残らないので、connect で付くのは `forked` だけ
- 持ち主だけが書ける置き場の symlink は `respelled` だけ
- 成功した時、`route` より前に試した経路はすべて「使えなかった」もの (実際に bind / connect して失敗したら、そこでエラーを返して次を試さない)。そのため「使えたか」の真偽値は持たず、通った経路と飛ばした経路を分ける
- `route`・`skipped` の名前と `reason` は診断用で、中身を約束しない。飛ばした経路と理由は、なぜその経路に落ちたかを利用者の手元で調べ、OS や使える手段ごとの整理に使える

### 失敗した時

- any 系が失敗した時も、エラーに `skipped` を付ける。実際に bind / connect して失敗した経路があれば、その名前 (`route`) も付ける (全部が使えなかった `ENAMETOOLONG` では無い)
- 付け方は各言語の慣習に従う。OS のエラーの errno はこれまでどおり取り出せる形を保つ (Rust は errno を持つエラー型に `skipped` を持たせる、Go は `Unwrap` で errno に届くエラー型、Python は例外の属性 等)

理由:

- 有効にする手間が「失うものを受け入れる」という意思表示になる
- 経路の名前を契約にすると、経路の追加・変更が破壊的変更になる。利用者が知りたいのは経路でなく失ったもの
- 失うものには大小が無く (fork と共有の置き場の symlink は互いを含まない)、標準の経路でも失うものが出うる。名前の並びなら、包含や順を考えずに足せる (kawaz 裁定 2026-11-19)
- 失敗した時こそ、なぜ届かなかったかを知りたい (kawaz 裁定 2026-11-19)

## Alternatives Considered

- 案 A: fork の無い言語の既定の bind に置き場の symlink を戻す
  - 不採用理由: 選んでいない利用者にも安全でない綴りを残す
- 案 B: `bind_any` の置き場を持ち主だけが書ける置き場に限る
  - 不採用理由: BSD 等で `/tmp` しか無いと届かない。「何が何でも」の意図に合わない (共有の置き場は最後で、`recreatable-spelling` で知らせる)
- 案 C: 失ったものを真偽値 (標準か、fork か、共有の symlink か) で返す
  - 不採用理由: 失うものが増えるたびに型が変わる
- 案 F: 失ったものを段階 (標準 / 綴り替え / fork / 共有の symlink) の 1 つの値で返す
  - 不採用理由: 失うものに大小が無いのに並びを作ることになり、新しい失うものを隙間に入れたくなる。標準の経路で通った時の注意も表せない
- 案 D: 経路の名前を契約として返す
  - 不採用理由: 経路の追加・変更が破壊的変更になる
- 案 E: 試した経路を `{名前, 使えたか, 理由?}` の 1 つの並びで返す
  - 不採用理由: 成功時は最後の 1 つだけが使えたものになるので、真偽値と省略できる理由が起きない組み合わせを許す

## Consequences

- `connect_any` 系の戻り値は `forked` の代わりに `losses`・`route`・`skipped` を持つ (Rust の `AnyConnection` の形が変わる。未 release なので影響なし)
- fork の無い言語 (Python、Go) は `bind_any` だけを出す

## 未確定

- `bind_any` に後始末つきの形 (`_ex`) を置くか、置くならその形は、各言語の案を見て決める
