## 裁定待ち

### DG-Q1: DGRAM の `send_to` を sockat の関数として作るか

SPEC の関数の表には `datagram::send_to` と `send_to_ex` が載っているが、経路が未確定のままで、どの言語にも実装が無い。各言語のマニュアルは今、「`resolve_for_connect` で作ったパスを、標準ライブラリの `send_to` に渡す」と案内している (sockat-rs の `docs/manual/datagram`)。

- 作る場合に決まっていないのは、resolve の綴りに収まらない長さの宛先をどうするか (スレッドの cwd を使って送るか、`ENAMETOOLONG` にするか)
- 作らない場合、利用者は resolve を 1 回呼んでから送る。同じ宛先に何度も送るなら、綴りを使い回せるのでその方が速い

- [ ] a: 作らない。SPEC の表から `send_to`・`send_to_ex` を外し、「resolve の綴りを標準ライブラリに渡す」を仕様の案内にする (統括の推し。SEQPACKET と同じ扱いで、今の実装とマニュアルのまま)
- [ ] b: 作る (収まらない長さの扱いも決める)

### DG-Q2: 長いパスに bind した DGRAM への返信が届かない場面を、仕様でどう表すか

SPEC の未確定に残っている問い。返信が届かないのは、綴りを片付けた後と、`/proc` を通る綴りに別の uid から送る時。

- 今の `Spelling` は、綴りがいつまで有効か (`until`) と、別の uid から辿れるか (`usable_cross_uid`) を既に持っている。Q&A (`pages/faq`) もこの 2 つで説明している

- [ ] a: 今ある `Spelling` で表せているので、未確定から外す。SPEC の DGRAM の節に「返信が届く条件は `Spelling` で分かる」と 1 文書く (統括の推し)
- [ ] b: 返信のための項目を `Spelling` に足す

### CL-Q3: CLI に `sockat run -- <コマンド>` と、片付けのサブコマンドを置くか

DR-0018 の未決。今の既定の `sockat <パス>` は、使い回す symlink を置くだけで片付けが要らない。

- `run` は、コマンドを包んで起こし、そのコマンドが生きている間だけ有効な綴りを渡す形。終われば自動で片付く
- 片付けのサブコマンドは、`run` や「持ち主の fd を渡す形」のように、片付けが要る綴りを作る口ができた時に初めて要る

- [ ] a: 今は置かない。要る利用者が出たら考える (統括の推し。既定の形で足りていて、使う人がまだ居ない)
- [ ] b: `run` を置く (片付けのサブコマンドも一緒に設計する)
