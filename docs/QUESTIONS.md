# 裁定・確認待ち一覧 (ユーザ用)

## 運用規約

<details>
<summary>ゼロコンテキストエージェント向け（本セクションは消さない）</summary>

- 裁定/確認待ち項目を 1項目=1ラベル=1セクション で記載
- ラベル形式: XX-Q1（XX は 2-3 文字、バッチやセッション内で一意、Qn単独の使い回し禁止、長期一意性は不要)
- 依頼形式: 「👺XX-Q1 の裁定お願いします」（参照用途ではラベルに👺を付けない。誤陽性がユーザのハイライト/アラームを汚す）
- チャット提示と同一ターンで本ファイルに記録 + path 指定 commit
- 裁定が下りたら該当セクションを即削除し、内容は正規の記録先 (DR / issue / journal) へ反映。本ファイルは常に「現在待ち」だけを持つ
- 参照は[]()で提示（リポ内は相対、リポ外はフルパス）
- 選択肢・確認項目は `- [ ] a: …` 形式（チェックボックス + ラベル）で書く

</details>

## 裁定待ち

### PB-Q2: パッチ版の公開を各言語のセッションに任せてよいか

SPEC に沿った直し (今日の字句で畳まない・空のパス・B 自身の x の見直し、RV-Q1・RV-Q2 の実装、文書の分け方) を各言語が手元に積んでいる (py 0.3.1、rs 0.5.2、go v0.4.1、ts の次の版)。

- [ ] a: 任せる。各言語のセッションが CI (BSD・illumos を含む) とハブの適合試験 (全言語) を通した上で、bump・push・release まで行い、結果をハブに知らせる。破壊的な変更を含む版 (0.x の minor を上げる物) は今まで通り kawaz に聞く
- [ ] b: 版ごとに kawaz に聞く

統括推し: **a**。理由: SPEC と適合試験で中身は揃えてあり、版ごとの確認は手順の往復だけになっている。悪い面: 公開の瞬間を kawaz が見ないので、CI の結果の読み違いがそのまま出る (ハブが結果を受けて確かめる)。
