## 裁定待ち

### DG-Q1: DGRAM の `send_to` を sockat の関数として作るか

SPEC の関数の表には `datagram::send_to` と `send_to_ex` が載っているが、経路が未確定のままで、どの言語にも実装が無い。各言語のマニュアルは今、「`resolve_for_connect` で作ったパスを、標準ライブラリの `send_to` に渡す」と案内している (sockat-rs の `docs/manual/datagram`)。

- 作る場合に決まっていないのは、resolve の綴りに収まらない長さの宛先をどうするか (スレッドの cwd を使って送るか、`ENAMETOOLONG` にするか)
- 作らない場合、利用者は resolve を 1 回呼んでから送る。同じ宛先に何度も送るなら、綴りを使い回せるのでその方が速い

- [ ] a: 作らない。SPEC の表から `send_to`・`send_to_ex` を外し、「resolve の綴りを標準ライブラリに渡す」を仕様の案内にする (統括の推し。SEQPACKET と同じ扱いで、今の実装とマニュアルのまま)
- [ ] b: 作る (収まらない長さの扱いも決める)
