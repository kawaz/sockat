### CP-Q2: CPython の `os.getcwd` の件を、公開の issue で出すか、非公開の窓口 (GHSA) に先に出すか

決まっていること (kawaz 2026-11-22): 報告はする。kawaz の名前で出す。下調べは [docs/research/2026-11-22-cpython-getcwd-over-path-max.md](research/2026-11-22-cpython-getcwd-over-path-max.md)。報告そのものは、まだ何も出していない。

- 下調べは「公開の issue が妥当」としたが、その理由のうち「止まるだけ」「引き金に被害者の cwd を作る力が要る (起動の条件)」は弱い (kawaz 2026-11-22)。深いディレクトリを作れる人が、そこを cwd にして動く他人の Python のプロセス (定期実行、ディレクトリごとに走る道具等) に、機械のメモリを使い切らせられる。cwd が変わった時点でなく、後で別の所が cwd を読んだ時に当たる
- 公開でよいと言える根拠で残るのは、当たる OS (illumos。推測で NetBSD・OpenBSD) が CPython の支援の対象外で、CPython の方針が「対象外の OS だけに当たる物は脆弱性として扱わない」と書いていること
- 公開は取り消せない。非公開で出して「公開でよい」と返されるのは数日の遅れで済む
