## 裁定待ち

### RV-Q1: `/tmp/sockat-<uid>` が確かめに外れた時、乱数の B に落とすか、次の置き場へ進むか

今は `sockat-<uid>.<乱数>` の B に落ちる (kawaz 2026-11-21 の「B の作り方」)。他の uid が `/tmp/sockat-<自分の uid>` を先に作ると、長いパスを使うプロセスごとに乱数の B が増え、`sweep()` の対象外で、macOS では再起動まで残る。

- [ ] a: 乱数の B をやめ、次の置き場 (`$XDG_RUNTIME_DIR` → `$TMPDIR` → ソケットのディレクトリ) へ進む。`skipped` の `reason` に占拠と分かる理由を入れる
- [ ] b: 乱数の B を残し、`sweep()` の対象にする
- [ ] c: 今のまま、説明に書くだけ

統括推し: **a**。理由: 増える物が無くなり、乱数の B という概念と `sweep` の例外が消える (置き場の順は既にある)。悪い面: 占拠された時、macOS は `$TMPDIR` (長く、dirhelper が 3 日で消しうる) に移るので、届く長さが縮み、`usable_cross_uid` は満たせず thread-cwd に進む。占拠は他人の悪意か事故の時だけなので、その時に縮むのは許容と見る。3 言語 + ts の変更 (次の版)。

### RV-Q2: 既定の bind の E を (D, ソケットのディレクトリ) ごとに 1 つにして使い回すか

既定の bind は E を bind ごとに作り、プロセスが終わるまで残す (片付けの口が無い)。同じディレクトリに何度も bind する長命の daemon では E が bind の数だけ増える。link-dir の E はディレクトリを指すだけなので、同じディレクトリへの bind は同じ E の下にファイル名を並べられる。

- [ ] a: 既定の bind に限り、E を (D, ソケットのディレクトリの realpath) ごとに 1 つにして使い回す。`_ex` と resolve は今のまま呼び出しごと (cleanup の単位を変えないため)
- [ ] b: 今のまま (長命の daemon は `bind_ex` の `remove()` を使う、の案内は SPEC と README に入れ済み)

統括推し: **a**。理由: 既定の bind は E を消さないので参照を数える必要が無く、プロセスの中の表 1 つで済む。同じディレクトリへの bind が多い daemon で E の増え方が bind の数からディレクトリの数になる。悪い面: 試験のように毎回違う一時ディレクトリへ bind する所では減らない (利用者の実測の E の多くはこちらの見込み)。link-file の E (ソケットのファイルを指す) は対象外。
