## 裁定待ち

### CL-Q1: CLI の `resolve` で、ファイル名が長くて用途の指定も無い時

[DR-0018](decisions/DR-0018-cli-resolve-with-reused-hashed-link.md) の「`resolve` の既定の綴り」の 6。

- 既定の綴り (ソケットのディレクトリを指す E を通す `B/<ハッシュ>/<ファイル名>`) は、bind にも connect にも使えるので用途を聞かない
- ファイル名が長くてこの綴りに収まらない時 (uid 4 桁で Linux はおよそ 77 バイト超、macOS はおよそ 66 バイト超) は、ソケットのファイルを指す E を通す綴りに回る。これは connect にはどの OS でも使えるが、bind に使えるのは macOS と NetBSD だけ
- 主な客は引数を増やしたくない。一方で、使えない綴りを黙って出すと、渡した先の bind が `EADDRINUSE` で失敗し、原因が分かりにくい

- [ ] a: 用途の指定 (`--for bind` / `--for connect`) が無ければエラーにして、指定を求める (統括の推し。使えない綴りを黙って出さない)
- [ ] b: 指定が無ければ connect 用とみなして出す (bind に使う人は `--for bind` を付ける)

### CL-Q2: 手法を試す口に、最初から入れる手法の範囲

[DR-0018](decisions/DR-0018-cli-resolve-with-reused-hashed-link.md) の「手法の名指し」。

- 今ライブラリにある手法は、CLI から名指しする入口を足せば試せる
- ライブラリに無い手法 (fork、bind での `/proc` を直接通す綴り・相対パス・広げた sockaddr) は、DR-0017 でライブラリから消した物で、CLI のためだけの実装と OS ごとの試験が要る

- [ ] a: まず今ライブラリにある手法だけで出し、無い手法は後から足す (統括の推し。主な客向けの `resolve` を先に出せる)
- [ ] b: 最初から fork 等も入れて出す

### RP-Q1: 相対パスを絶対にした形で届かない時

[DR-0019](decisions/DR-0019-absolutize-relative-path-on-bind.md) の「絶対パスの作り方と、その後」の 5。

- bind と resolve は、相対パスを cwd で絶対パスにしてから扱う (kawaz 2026-11-22)
- 絶対にした形が長く、置き場も作れない等でどの経路も使えない時や、cwd を引けない時がある。元の相対パス自体は短く、標準なら bind できる

- [ ] a: 相対のまま標準に渡す (統括の推し。標準で届く所に届かなくならない。この時だけ綴りは相対で、`Spelling` は `CwdRelative`)
- [ ] b: エラーにする (相対の綴りを決して残さない。標準なら届く場面で届かなくなる)

### RP-Q3: 長い絶対パスの bind でも、実パスが収まればそれを使うか

[DR-0019](decisions/DR-0019-absolutize-relative-path-on-bind.md) の候補の考え方を、相対パスだけでなく長い絶対パスにも当てるか。

- 途中の symlink のせいで長く見えるだけの絶対パスは、実パス (ソケットのディレクトリの realpath + ファイル名) にすると上限に収まることがある。収まれば標準にそのまま渡せて、置き場に何も作らない
- 今のライブラリは、長い絶対パスをいつも置き場を通す経路に回す
- CLI の `resolve` は、先に実パスを試す形にした (統括、2026-11-22)

- [ ] a: ライブラリの bind と resolve も、長い絶対パスで先に実パスを試す (統括の推し。CLI と揃い、置き場に作る場面が減る。カーネルが覚える綴りは実パスになる)
- [ ] b: ライブラリは今のまま (長い絶対パスは置き場を通す経路)。実パスを試すのは相対パスと CLI だけ

### RP-Q4: connect 用の resolve が返す物にも、綴りの性質を持たせるか

- bind 用の resolve が返す `ForBind` は、綴りの性質 `Spelling` を持つ (相対のままなら `CwdRelative`、`/proc` を通す綴りなら「プロセスが終わるまで」等)
- connect 用の resolve が返す `ForConnect` は、綴り (`path`) と `cleanup()` と診断だけで、`Spelling` を持たない (DR-0017 が「connect の綴りは相手に残らないので返さない」とした)
- resolve の綴りは利用者が持ち続けて後で使う物なので、「相対のままなので cwd を変えると使えない」「`/proc` を通すのでこのプロセスの間だけ」は connect 用でも要る (kawaz 2026-11-22: resolve した綴りを長く持つなら、cwd が変わると使えないことが分かればよい)

- [ ] a: `ForConnect` にも `Spelling` を持たせる (統括の推し。今ある型をそのまま使う。bind だけに意味のある `removable` は、connect 用では使わない値として説明に書く)
- [ ] b: `ForConnect` は今のまま。相対の綴りを返しうることは説明に書くだけにする
