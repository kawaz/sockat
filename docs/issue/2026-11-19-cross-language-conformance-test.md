# 言語によらない適合試験

経路は 16 個あり、3 言語 (今後は 5 言語) がそれぞれ試験を書いている。2026-11-19 だけでも skipped の中身や失敗時の route で言語ごとの食い違いを何度も直した。人の突き合わせに頼らず、同じ入力で同じ結果になることを機械で確かめる。

## 形 (案)

- 各言語に試験用の小さな CLI を付ける (例: `bind <path>` / `connect <path>` を実行し、`losses`・`route`・`skipped` の名前・errno を JSON で出す)
- ハブの justfile から、同じ入力の表を各言語の CLI に流し、結果を突き合わせる
- まず経路を強制しなくても作れる場面から: 短いパス、長いパス、相対パス、ディレクトリが無い、`ENOTDIR`、`EADDRINUSE`
- 経路の強制 (SPEC の「環境を読む部分は試験から差し替えられる」) を CLI から操作できるようにするのは後から足す

## 着手の条件

- `_ex` への any の統合 (公開 API の形) が決まってから

## 悪い面

- 各言語に CLI と、強制の差し替えを外から操作する口が要る
