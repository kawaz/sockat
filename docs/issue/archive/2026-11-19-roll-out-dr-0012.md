# DR-0012 を SPEC の残りと各言語に行き渡らせる

閉じた理由: 3 言語が DR-0012・0015・0016 を実装して公開した (sockat-rs 0.4.1、sockat-py 0.2.1、sockat-go v0.3.0)。利用者 (llm-gateway、hyoui) に知らせた。

## ハブで残っていること

- [x] D をどこにも作れない時の bind も D 無しの形でスレッド cwd → /proc 版 → fork (D12-Q1 = a、DR-0012 と SPEC に反映済み)
- [x] README (日英) の「共通の振る舞い」を DR-0012 の経路に合わせる
- [x] connect の fork と FreeBSD の connectat は D を通さない (D12-Q2 = a、反映済み)
- [x] SPEC を経路の名前と失うもので組み直す、使ってはいけない書き方の節
- [x] any 系を `_ex` に統合する (kawaz 裁定、DR-0015)。3 言語の作り直しは依頼する
- [x] 経路の名前の変更 (fork → fork-cwd 等、symlink → symlink-file / symlink-dir) と、bind の symlink-file (kawaz 裁定、DR-0016)。3 言語の作り直しは依頼する
- [x] connect の試す順番を、書き込みもスレッドも要らない経路を先にする (kawaz 裁定、DR-0012 と SPEC の「connect の順」に反映済み)
- iOS 等 macOS 以外の Apple の OS は [2026-11-19-ios-long-path-bind](../2026-11-19-ios-long-path-bind.md) に分けた (kawaz が iOS で試す機会ができた時に決める)
- 言語によらない適合試験は [2026-11-19-cross-language-conformance-test](../2026-11-19-cross-language-conformance-test.md) に分けた

## 各言語の状態

公開: sockat-rs 0.4.1 (crates.io、2026-11-19)、sockat-py 0.2.1 (PyPI、2026-11-19)。sockat-go v0.3.0 (2026-11-19)。sockat-go は illumos で先頭 NUL / `@` を abstract として標準に渡す SPEC との食い違いを v0.3.1 で直す (sockat-go の docs/issue/2026-11-19-illumos-abstract-names.md)。llm-gateway と hyoui の統括に 0.4.1 の変更点を知らせた。公開後の `just conformance` は 3 言語 14 場面で差なし。

2026-11-19 夕方時点 (ハブ main = bcc8d9b1):

- 3 言語とも DR-0012 (connect の順を含む)・DR-0015 (`_ex`)・DR-0016 (経路の名前、bind の symlink-file)・相対パスの bind_ex の cwd の比較を実装済み。適合試験 (`just conformance`) は 3 言語 14 場面で差なし
- kawaz の release の OK が出た (2026-11-19)。sockat-rs 0.4.1 (0.4.0 は crates.io に出ないまま欠番)、sockat-py 0.2.1 (0.2.0 は欠番)、sockat-go v0.3.0 の見込み
- sockat-rs と sockat-py は push した CI で試験が落ちて release が止まっている (公開はされていない)。各言語で直している
  - 両方で「置き換えたソケットのファイルを discard が消さない」試験が GitHub の ubuntu と BSD で落ちた。原因は listener を閉じた後の inode 番号の使い回し (ext4 で実測、FreeBSD・NetBSD は CI の結果から推定。[findings](../../findings/2026-11-19-inode-reuse-after-close.md))。kawaz 裁定 (2026-11-19): `(st_dev, st_ino)` のまま、約束を listener を開いている間の置き換えまでに狭め、閉じる前に呼ぶよう勧める (SPEC、DR-0015)。各言語は試験を開いたまま置き換える形にし、説明を直してから release する
  - 他の落ち方は試験の作りの不具合 (CLI の import パス、OpenBSD / illumos で長い bind を準備に使っていた、NetBSD の symlink-file の前提)。各言語が直している
- bind が symlink を辿るかの実測 (sockat-py の CI): 辿るのは macOS と NetBSD、辿らないのは Linux・FreeBSD・OpenBSD・illumos。SPEC と DR-0016 に反映済み。sockat-go に Listen の symlink-file を OS で絞るよう依頼済み
- CI の job の再実行は、どのセッションでも確認なしで良い (kawaz)

release したら llm-gateway 統括 (connect_nonblocking だけ使用) と hyoui 統括 (bind / connect / connect_nonblocking) に知らせる。
