# 短い綴りを作る CLI と、手法を名指しして選ぶ口 (CLI と `_ex`)

## 概要

kawaz の案 (2026-11-22)。CLI は作る。残りは検討中で、裁定はまだ無い。

- 短い綴りを作って出す CLI を作る。sockat を組み込めないプログラム (他人の作ったコマンド) に、長いパスの代わりに渡す
- CLI は引数で条件と手法を選べる。手法を指定して作れなければエラーにする
- 手法の名前を並べて、その順に試させる口も欲しい。API (`_ex` の引数の戦略の設定) に入れてもよく、そこでなら fork の手法を戻してもよい
- `/proc` を通る綴りも CLI で使える。利用者が開いたディレクトリの fd を渡すオプションを置き、`/proc/<持ち主の pid>/fd/<N>` を B として使う

## 分かっていること

### CLI が出した綴りの寿命

- `/proc/<pid>/fd/<fd>/…` の綴りは、その pid のプロセスが fd を持っている間だけ辿れる (SPEC の `until: Process`)。CLI 自身の pid と fd で作ると、CLI が終わった時に辿れなくなる
- 持ち主を呼ぶ側のプロセス (シェル等) にすれば成り立つ。別のプロセスが同じ uid で `/proc/<pid>/fd/<fd>/D/E/<名前>` に届くことは実測済み (DR-0017 の Context)
- 既定の B (`/tmp/sockat-<uid>`) の中に CLI が D を作ると、flock を持つプロセスがいなくなり、他の利用者の `sweep()` と OS の掃除で消されうる。利用者が持つディレクトリを B にすれば、これは起きない
- 使えるのは Linux で `/proc` を使え、同じ uid・同じ PID 名前空間の相手だけ

### 持ち主の pid を親の pid から決める時の罠 (実測 2026-11-22、macOS)

コマンド置換の中で起こしたプロセスから見た親の pid が、呼んだシェル本体か。

| 起こし方 | bash 3.2 | zsh | dash |
|---|---|---|---|
| `$(cmd)` | 本体 | 本体 | 本体 |
| `$(cmd \| cat)` | 別 (すぐ終わる) | 別 | 別 |
| `$(true; cmd)` | 別 | 本体 | 本体 |
| `$(env cmd)` | 本体 | 本体 | 本体 |

- 親の pid を黙って使うと、パイプや複文の中で、すぐ終わるプロセスを持ち主にしてしまう。`/proc/<pid>/fd/<N>` と渡された fd の `(st_dev, st_ino)` の照合は、その時点で同じディレクトリかしか見ないので、すぐ終わる親を見分けられない
- 持ち主の pid は引数で受ける (シェルなら `$$`) 形が候補

### CLI で選ぶ物

- 綴りが指す物: ソケットのディレクトリ (link-dir。渡した先が名前を足す・rename する・unlink するのに耐える) か、ソケットのファイル (link-file。ファイル名の長さによらない)
- B の綴り: `/proc` を通すか、実パスか
- B の置き場: 自動か、渡されたパスか、渡された fd か
- 用途: bind か connect か (今の resolve の 2 つ)
- 条件を満たせない時に満たさない綴りに落とさずエラーにする形は、`usable_cross_uid` と resolve が既に取っている

### 既に決まっていることとの関係

`_ex` で手法を名指しする口と fork の復活は、次を覆す。

| 決まっていること | 出どころ |
|---|---|
| 経路を利用者が選ぶ・組み合わせる口は作らない (「素人が下手な組み合わせで微妙な使い方をする意味は無い」) | DR-0017 の案 U、SPEC の「公開する操作」(kawaz 2026-11-19) |
| 経路の名前は診断用で、中身を約束しない (契約にすると経路の追加・変更が破壊的変更になる) | DR-0017 の案 V、SPEC の「診断」 |
| fork の経路を作らない。最終手段の引数も無い (副作用がプロセス全体に及ぶ。3 言語で届く所がそろう) | DR-0017 の「fork をしない」と案 J (kawaz 2026-11-20) |

- 分かれ目は「経路の名前を約束に入れるか」。入れれば、除く・足す (fork を含む)・順を変えるを 1 つの並びで表せる。入れなければ、条件ごとの引数を足す形になる
- bind に使ってはいけない手法 (proc-direct・relative・at-direct は綴りが後で無関係なファイルに当たる、widened はアドレスが切れて読む側を壊す) は、名指しされても通さない制限が要る
- fork を作れるのは Rust だけ (Python は難しく、Go と TypeScript は作れない。[fork-cwd](../../pages/fork-cwd-ja.md))
- 利用者 2 つの回答 (2026-11-20) は「fork をやめても困らない。当たるのは seccomp の下でファイル名 80〜96 バイトの時だけ」

## 未決

- 経路の名前を約束に入れるか
- `_ex` の bind / connect で、手法を名指し・並べ替えたい具体の場面 (除きたい: スレッドを立てない、置き場に書かない、`Dangling` なら失敗。足したい: fork)
- CLI をどのリポ・どの言語で作るか (ハブにはライブラリのコードを置かない)
- CLI の形: 綴りを出すだけか、コマンドを包んで起こす形 (flock の fd を継がせれば D が生き続ける) も置くか
- 片付けの口 (CLI が作った E を誰がいつ消すか)
